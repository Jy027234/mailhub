feat(ui): audit the React workspace in a real browser and gate it

Adds the rendering half of the WCAG 2.2 AA gate.  jsdom has no layout engine,
so contrast, target size, reflow and motion could only be asserted by hand;
they now run in headless Chromium through the Vitest browser runner against the
shipped stylesheet.

Measured:
  1.4.3/1.4.11  five views, 0 violations and 0 axe "incomplete"
                (12-22 elements actually measured per view)
  1.4.10        320 CSS px: no horizontal scrolling, inbox collapses to one track
  1.4.4         640 CSS px: no horizontal scrolling
  2.5.8         smallest control 26.0 CSS px (floor is 24)
  2.3.3         no motion by default; with prefers-reduced-motion emulated over
                CDP an injected transition-duration: 3s is clamped to 1e-05s
  CSP           no inline style attributes unless the theme prop is used

Every claim carries a liveness probe: deliberately low-contrast text, two
12x12 buttons with no spacing, and a document-level audit with <html lang>
removed.  If an axe rule stops running the probes fail first instead of the
suite going green.  The third probe also exposed that page-level rules are
invisible to a container-scoped axe.run, so the audit now has component- and
document-scoped entry points.

check_ui_browser_a11y.py refuses to trust the exit code: it requires at least
15 passing tests, all three views measured for target size, at least five views
measured for contrast, and re-checks the 24 CSS px floor from the run's own
output.  A missing npm, node_modules or Playwright browser fails, never skips.

Also corrects the accessibility item's ID: the adoption-readiness doc labelled
it MAIL-UX-011, which collides with an unrelated feature item in the master
todo; the item is MAIL-UX-010.
