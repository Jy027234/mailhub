# MailHub 用户手册

MailHub 用于在授权范围内整理常用邮箱、识别项目/任务/知识候选和准备回复草稿。
它默认是 metadata-first：先显示主题、参与者、时间、账号、标签和候选状态，正文和
附件按需、按权限读取。

## 收件箱

- 通过账号标识区分多个邮箱；使用未读、重要、附件、项目和候选筛选。
- “加载更多”使用不透明、范围绑定的 cursor；不要复制 cursor 到其他用户、账号或筛选
  条件。
- 搜索会显示覆盖范围和完整性。当前 metadata 搜索可能不完整；Provider 搜索未验证时
  会返回 degraded，而不是伪装成全量结果。

## 候选和草稿

- 项目、任务、知识候选都必须显示来源 ref、revision、置信度/风险和当前状态。
- 审核前可驳回并填写原因；批准不会绕过宿主的项目/知识权限。
- 草稿的收件人、正文、附件 ref 和 revision 会参与 digest。发送前仍需人工确认、策略
  与授权；MailHub 不会因为邮件内容自动扩大收件人、OAuth scope 或附件权限。

## Agent 自主运行

当前可用的是 owner-scoped `recommend_only`：收取、去重、分类、摘要、生成候选和草稿。
运行可暂停、恢复、取消和重放，但不能直接发布知识、修改项目或发信。连接撤权、提示
注入或策略变化可能自动暂停，需人工查看原因后恢复。

## 连接、导出和删除

连接中心显示账号、Provider、scope、内容模式、同步健康和删除影响，并提供默认不含正文的元数据导出；含正文导出需要二次确认。M2 Gmail、M3
Graph 的真实授权/同步目前处于受控 preflight；界面中的 preflight/degraded 是预期状态。用户可请求
bounded export；在删除前也可以先“仅撤销访问”，保留连接投影核对 Provider 已停止访问；删除完成前不要假设正文、对象或知识下游已经消失。

遇到“需要重新授权”“Provider 不可用”“结果未知”或“候选需审核”，请保存页面上的
错误码/trace ref，联系管理员，不要重复点击发送。真实邮箱测试应只使用组织批准的隔离
账号。
